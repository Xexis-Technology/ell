Related lesson: a `<p class="label">` placed as a direct child of a CSS grid becomes a grid cell — never mix bare labels into a layout grid; use real section headings.
- **CSS gotcha (admin):** grid/flex children default to `min-width:auto`, so a wide `<table>` inside a card silently stretches the whole page. Any admin grid must use `minmax(0,1fr)` tracks plus `min-width:0` on children; verify with `scrollWidth > clientWidth` checks, not by eyeballing screenshots.
- **Verification gotcha (this machine):** Chrome headless has a ~496px minimum window width, so `--window-size=430` produces a 496px layout captured into a 430px image and looks falsely broken. To test true narrow viewports, load the page in a fixed-width same-origin `<iframe>` (360/390/430px) and measure/assert from inside it.
- **Verification gotcha (auth):** injecting a session cookie into Chrome's `Default\Network\Cookies` does not work here — Chrome purges plaintext and even DPAPI-encrypted rows. Reliable method: a temporary throwaway PHP file that calls `login_user('admin', $u)` then redirects; Chrome stores the cookie itself. Delete the file afterwards.
- **2026-10-05 dispatch board (frontend-design):** the admin dispatch page is a **run sheet**, not a table — ordered by departure time with a time rail and real idle-gap markers ("2 h 45 m clear"). Reason: a chauffeur board's organising axis is time, and "how much slack is left" is the question the page exists to answer.
- **Two-accent rule for admin operations:** brand champagne (`#D9B978`) = the promise (public site, primary action button). New amber `#E8A33D` = the working instrument (departure times, "needs a driver", today's live state). Sodium-vapour amber is what a night dispatch board looks like, and it keeps operational state from competing with brand actions. Never use amber as the only signal — pair it with text.
- **Encoding rule (learned the hard way):** never put literal non-ASCII punctuation (·, →, —, ') in PHP source written via tooling on this machine — an edit round-trip can write `Â·` / `â€²` into the file and it renders as garbage. Use HTML entities (`&middot;`, `&rarr;`, `&mdash;`, `&#39;`). When a page shows `Â§`-style junk, check the *source file bytes* first, then the HTTP `Content-Type`, then suspect your own reading of the screenshot.
- **Validation rule:** a regex is not a date check. `preg_match('/^\d{4}-\d{2}-\d{2}$/')` accepts `2026-13-45` and then `strtotime()` returns false, which fatals downstream. Use `DateTime::createFromFormat` and verify it round-trips (`$d->format('Y-m-d') === $input`). Apply this to every `?day=` / `?from=` / `?to=` parameter.
- **Replacing a native `<select>` changes the POST contract.** An empty `<option value="">` posted `''`, but a JS picker posts `0` for "nothing selected". `$_POST['x'] !== '' ? (int)$_POST['x'] : null` turns that into `int 0`, which passes the falsy availability checks and then dies on the foreign key. Always normalise with a helper that maps `''`, `'0'` and `0` to `null`, and test the clear path as carefully as the set path.
- **Absolute popovers and `100vw` math:** a `position:absolute` box anchored to a trigger at a variable indent cannot be sized safely in viewport units — it will push the page into horizontal scroll at some widths and not others. Fix by changing *mode* with the layout instead of by arithmetic: below the point where the form goes single-column, render the panel inline (static, grows the form); above it, float it and anchor the right-hand one to the trigger's right edge. Keep the float/inline breakpoint identical to the form's column breakpoint.
- **Popover payload:** ship shared JSON once as `<script type="application/json">` with `JSON_HEX_TAG|JSON_HEX_AMP|JSON_HEX_APOS|JSON_HEX_QUOT`, then `JSON.parse(...).textContent`. Never inline JSON into `x-data="{...}"` — this codebase already got burned by that once (see the blank-form fix).
- **2026-10-05 client book (frontend-design):** the admin now has ONE instrument language across pages — mono for anything that identifies or dates, amber for "needs a person or a decision", green for settled, champagne serif reserved for the client's name and money. The client book is the ledger facet of that same system, not a separate theme. The deliberate risk: **lifetime billed is the largest type on the page**, because a limo company lives on repeat clients, so the relationship's value is the real headline. Most admin pages lead with a row count.
- **Use container queries for anything inside a multi-column admin layout.** A viewport media query cannot know how wide a panel actually is: at a 1080px window the two-column customer split leaves the sheet ~440px, where five fixed table columns collapse the flexible one to 0px and overflow the card — while the same viewport at a single-column breakpoint looks perfect. `container-type: inline-size` + `@container name (min-width: …)` is the correct tool.
- **`COUNT(*)` over a LEFT JOIN counts rows, not entities.** `SELECT COUNT(*) FROM customers c LEFT JOIN bookings b ...` reports a client with 7 rides as 7 clients. Use `COUNT(DISTINCT c.id)`. Always assert a header count against a direct `SELECT COUNT(*) FROM customers` before calling a page done.
- **2026-10-05 fleet & crew (frontend-design):** the two Fleet pages are **dockets**, not tables, sharing one `fl-*` component set. The signature is the compliance clock: bar length = time remaining against a 12-month horizon, colour = urgency. Length and colour are deliberately **two independent channels** — an early version encoded both in length and made a lapsed document draw the longest bar, which read backwards.
- **Schema is not the product.** `vehicles.insurance_expiry / registration_expiry / inspection_expiry / diamond_sticker_expiry` and `drivers.license_expiry / reference / license_number / payout_reference` had existed in `database.sql` for weeks with no form writing them, so every value was permanently NULL. When redesigning a page, diff the table's columns against the form's inputs — the gap is usually the actual bug.
- **Iterate by index (`foreach ($rows as $i => $r) { $rows[$i][...] = ...; }`), not by reference, when enriching rows.** The by-reference form needs a matching `unset($v)` or every later loop silently aliases the last row; the index form has no footgun and reads the same. The actual fleet-docket bug was worse: the enrichment loop looked the four dates up through a `$WATCH` key=>label map **by label** instead of by column, so every lookup missed, all six cars counted as missing dates, and the filters collapsed to a single bucket. When a derived figure is uniformly wrong, dump the raw value and the computed value from the same loop before touching the math.
- **One SQL list cannot serve both UPDATE and INSERT.** `SET col=?` is valid for UPDATE but `col=?` is a syntax error in an INSERT column list. Build a bare column list and derive the `SET` form from it.
